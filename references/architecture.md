# 回归中心架构

## 组织原则

回归验证按业务板块组织，不按仓库或编程语言组织。一个业务板块可以同时覆盖后端、管理平台、客户端和节点核心；仓库只是检查的执行位置。

原生测试继续由所属仓库维护：各语言测试、构建和平台脚本都不复制进统一入口。回归中心只维护以下信息：

- 仓库路径与默认分支；
- 业务板块、触发路径和跨板块依赖；
- 稳定检查 ID、命令参数、工作目录、超时、风险和前置文件；
- quick、completion、full、release、runtime、migration、real-device、post-release 等配置档；
- 原生验证入口清单、已知失败和脱敏报告。

## 标准目录

```text
regression/
  run.*
  catalog.json
  checks.json
  native_test_inventory.json
  codex_rework_inventory.json  # 仅在用户授权历史晋升时使用
  known_failures.json
  modules/<module-id>/module.json
  profiles/<profile>.json
  schema/
  tests/
  reports/
```

已有项目可以使用等价结构。技能必须优先适配项目现有约定，禁止并行建立第二套回归入口。

## 选择模型

`changed` 模式必须同时读取相关仓库的工作区、暂存区、未跟踪文件，并按需比较默认分支到当前提交的差异。命中板块后递归补齐 `depends_on`；框架级、规则级或明确标记 `always` 的板块始终执行。

`module` 模式用于开发过程中的专项验证。`full` 强制选择全部板块，`release` 在全量自动化基础上增加发布构建。真实进程、外部服务、数据库迁移、USB 真机和生产回读分别进入风险明确的配置档，不得伪装成普通完工通过。

项目启用 Codex 重复返工晋升时，统一入口应在加载板块前增量同步脱敏清单，晋升板块标记 `always`。同步只能改变检查映射，不得把运行态、真机、迁移或生产检查提升到 completion 可执行风险范围。

## 命令契约

命令必须保存为参数数组，禁止保存可任意拼接的 shell 字符串。每项检查必须有稳定 ID、中文或项目规定语言的标题、仓库、类型、层级和风险；命令检查还要声明工作目录、超时和必要前置文件。

统一入口应保存结构化、脱敏、可回读的报告。编排器不能通过清空数据库、Redis 或队列替代原测试的隔离与恢复责任。
