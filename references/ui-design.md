# UI 与设计图回归

## 建模边界

UI 回归按用户可感知的业务表面组织，不按管理端、移动端、桌面端或具体技术框架拆散。每个表面至少登记实现路径、设计源、业务状态、视口、检查 ID、证据配置档和比较方式；没有 UI 的仓库必须明确标记 `not_applicable`，不能用空检查伪装覆盖。

项目存在 `regression/ui_design_inventory.json` 时，确定性审计器会校验仓库、表面、检查、配置档和 `ui-design` 模块引用。项目自己的框架自测还应从 Git 跟踪、暂存和未跟踪文件重新发现页面、组件、样式、路由、客户端视图、资源、UI 测试与设计工具，要求每个候选恰好映射一次。

## 设计源优先级

1. 原始设计文件、设计标注平台属性或项目明确批准的设计节点是几何、字号、行距、字距和设计倍率的权威来源。
2. 代码中的设计令牌和结构测试用于守住可重复契约，但不得扩大为未经批准的新设计基线。
3. 截图用于验证空白、遮挡、溢出、裁切、主题、状态和交互。存在权威标注时，禁止从 PNG 或截屏反推布局参数。
4. 没有批准设计源时，记录 `not_provided` 和原因，并把需要人工判断的视觉验收放入 `runtime` 或 `real-device`；缺少新鲜证据必须保持 `BLOCKED`。

## 检查分层

- `completion` / `full`：清单唯一映射、静态分析、组件测试、构建、设计标注与资源引用审计。
- `runtime`：真实浏览器多视口、桌面固定画布、主题、长文本、加载/空态/错误态、弹窗和交互证据；权威原始设计源缺失也在此明确阻断。
- `real-device`：主应用真实设备页面、系统安全区、键盘、隧道或平台状态与截图证据。项目禁止测试专用应用包时不得借测试运行器绕过。
- `post-release`：只有项目明确要求线上视觉回读时才进入，默认只读。

Golden、MAE、像素差异或人工叠图只有在项目明确批准基线、阈值和更新流程时才能作为门禁。否则保留结构、标注和运行态证据，不得为了绿色结果制造脆弱像素阈值。
