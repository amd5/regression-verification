# Codex 重复返工晋升

## 授权和读取边界

只有用户明确授权扫描 Codex 历史时才能读取会话目录。授权范围必须全量处理，不按日期、标题、关键词或仓库抽样；大文件使用 JSONL 流式读取，活动文件在扫描开始时记录大小快照。增量缓存只能保存在用户本地 Codex 缓存目录，不能进入业务仓库或技能包。

## 完整循环

同一目标的一次完整循环必须同时满足：Codex 在更早轮次写入过目标；后续用户消息明确要求还原、改回、撤销或指出误改；该轮 Codex 再次写入相同目标。目标可以是精确仓库相对路径、具体业务模块或真实用户界面表面，每轮同一目标最多计一次，至少三个独立循环才晋升。

项目规则、环境上下文等客户端注入必须先剥离。技术 `rollback` 契约、故障/连接/节点/数据/服务恢复、仅讨论或规划还原、没有再次写入、两次及以下，以及过宽的跨端总模块不得计数。UI 聚合只适用于真实 web、mobile、desktop、shared 表面；test、tooling、assets 和 governance 分类不能冒充用户界面。

## 映射与隐私

UI 优先通过项目 UI 表面清单映射稳定检查，程序代码通过具体业务模块触发路径映射；没有具体模块时可以使用仓库级稳定测试作为精确路径的保底检查。晋升板块应标记 `always`，但 completion 仍只能执行项目允许的 tier 和 risk；runtime、migration、real-device 和 production 证据不得因历史晋升越权执行。

提交清单只允许包含仓库相对路径、模块或界面 ID、循环数、时间、稳定检查 ID 和不可反推原文的截断哈希。禁止保存会话正文、用户消息、命令原文、凭证、完整会话 ID 或任务 ID。CI 没有本地会话目录时应审计已提交清单，不得伪称重新扫描通过。
